# 前端 Gherkin 測試劇本 — LINE AI 店家機器人 SaaS

> 放 `e2e/features/frontend/`。繁中「假設／當／那麼」。斷點一律 px：1024 為表格/卡片分界。

## F1. 響應式三裝置（電腦/平板/手機）

```gherkin
功能: 一套版面自適應三種寬度
  背景: 店家已登入後台「對話紀錄」頁

  場景: 電腦 1440px
    當 視窗寬度 1440px
    那麼 顯示左側側邊欄常駐
    並且 對話清單以表格呈現（多欄）
    並且 沒有底部導覽列

  場景: 平板 800px
    當 視窗寬度 800px
    那麼 側邊欄收成漢堡選單
    並且 對話清單以卡片雙欄呈現

  場景: 手機 390px（LIFF 實際寬度）
    當 視窗寬度 390px
    那麼 底部顯示導覽列（知識/對話/用量/設定四個 SVG 圖示）
    並且 對話清單為單欄卡片
    並且 頁面不出現橫向捲軸（scrollWidth 等於視窗寬）
    並且 按鈕點擊區 ≥44px

  場景: 邊界 1023 與 1024 都驗
    當 視窗寬度 1023px
    那麼 走卡片版面
    當 視窗寬度 1024px
    那麼 走表格版面
```

## F2. 知識庫（店家最常使用）

```gherkin
功能: FAQ 編輯與儲存回饋
  場景: 新增一題 FAQ
    假設 店家在知識庫頁
    當 按「新增 FAQ」，填問題與答案，按儲存
    那麼 按鈕顯示「已儲存 ✓」綠色狀態
    並且 1.5 秒後按鈕恢復原狀
    並且 FAQ 清單出現新的一題

  場景: 手機版編輯走全螢幕頁
    當 視窗寬度 390px 並按「新增 FAQ」
    那麼 編輯表單佔滿全螢幕，頂部有「←」可返回列表

  場景: 儲存失敗有紅字提示
    當 儲存 API 回傳失敗
    那麼 顯示紅色「儲存失敗，請重試」
    並且 已填的內容保留不清空
```

## F3. 對話紀錄篩選

```gherkin
功能: 三種狀態篩選
  場景: 只看未命中
    假設 對話紀錄有已解決、待真人、未命中三種
    當 店家點「未命中」篩選
    那麼 清單只顯示未命中的對話
    並且 每筆未命中都有「加入知識庫」操作

  場景: 待真人紅點計數
    當 有 3 筆待真人對話未處理
    那麼 選單「待真人處理」旁顯示紅點 3
```

## F4. 綁定設定

```gherkin
功能: 貼金鑰與 webhook 網址
  場景: 複製 webhook 網址
    當 店家點網址旁的「複製」按鈕
    那麼 出現「已複製」提示
    並且 webhook 網址格式為 /webhook/<店代號>

  場景: 金鑰預設遮罩
    當 店家進入綁定設定頁
    那麼 channel secret 與 access token 顯示 •••• 遮罩
    並且 畫面上任何位置看不到明文

  場景: 圖示全站 SVG、無 emoji
    當 逐一檢查導覽列、按鈕、狀態徽章
    那麼 所有圖示都是 <svg> 元素
    並且 頁面無 emoji 字元
```

## F5. 平台中台（管理員）

```gherkin
功能: 總覽與店家管理
  場景: 管理員看到全平台 KPI
    假設 Fish 以平台管理員登入中台
    當 開啟總覽頁
    那麼 看到店家數、本月 AI 回覆、AI 費用（NT$ 千分位）、待真人數四張卡

  場景: 停用店家
    當 管理員在店家列表按「停用」
    那麼 該店家狀態變「停用」
    並且 該店家 webhook 立即回 403，AI 不再回覆

  場景: 管理員看不到店家金鑰
    當 管理員開啟任一店家詳情
    那麼 金鑰欄位只顯示遮罩
```

## F6. Landing Page

```gherkin
功能: 對外介紹頁
  場景: 未登入訪客
    當 訪客開啟首頁
    那麼 看到一句話價值主張、三步驟、價格
    並且 「店家登入」按鈕導向 LINE Login
  場景: 手機版
    當 視窗寬度 390px
    那麼 主 CTA 按鈕滿寬置底，可單手點擊
```
